## 1. 정해진 것

| 항목 | 결정 |
| --- | --- |
| 엔진 3개 | **A. 격자·평면** / **B. 시간축** / **C. 관계 표 린터** |
| **툴을 안 쪼갠다** | 장르별로 나누지 않는다. 장르 차이는 **도면 프로필**(범례 + 켤 검사 목록)로 흡수 |
| **C 는 검사 도구** | 그림은 Mermaid 가 그린다. 우리는 표를 훑어 구멍을 잡는다 |
| 타일맵의 정체 | 그림이 아니라 **2차원 배열**. 그래서 AI 가 써도 안전하다 |
| 표기법 | 문자 그리드 + 범례. 코드펜스 태그는 ` ```tilemap ` |
| **축 3개 반영** | 도면을 바꾸는 건 **이동 축 하나뿐.** 투영은 렌더러만, 방향 수는 무관 |
| 격자의 뜻 | 중력+점프 = **옆에서 본 단면** / 평면 = **위에서 본 평면도** |
| 검증기 4번 | 중력+점프 = 점프 아크 / 평면 = **이어짐 검사(flood fill)** |
| Mermaid | 상태도·흐름도는 만들지 말고 **Mermaid 규칙만 정한다** |
| 방언 | `roomtemplate`(방 템플릿, 출입구 4방향) · `puzzle=sokoban`(XSB 표준 그대로) |
| 표기 문자 | **정본은 ASCII.** 눈에 편한 건 렌더러가 한다 (네모 기호는 폭이 모호해 정렬이 깨진다) |
| 곡선 그래프 | **안 만든다 (확정).** 조사 세 편이 각각 "표로 한다"고 확인 |
| 안 만들 것 | 곡선, 정밀 히트박스, 콤보 트리, 아스키 박스 그림, **시뮬레이터·밸런스 봇·던전 생성기** |
| 만들 언어 | **Node** (렌더 결과가 HTML 이라 자연스럽다) |

## 4. 아직 못 정한 것

- 엔진 C 표를 마크다운 표로 받을지 CSV 로 받을지
- 색 있는 문·열쇠 짝 (빨간 열쇠는 빨간 문만). 지금은 짝 없는 방식만 쓴다
- 열쇠가 모자랄 때 **어느 문을 먼저 열지** — 지금은 먼저 만난 문부터 연다. 드물게 최선이 아닐 수 있다
- 도달 가능성 검사 범위 — 평면은 대각선·대시, 중력은 더블점프. **둘 다 처음엔 뺀다**

**정해진 것 (2026-08-21)**
- 타일 기호와 보기 매핑 → `Guide/타일기호.md`
- 도면 프로필은 **그림 툴 프로필과 파일을 따로 둔다** (`Tools/Draw/profiles.json`). 읽는 쪽이 다르다
- 곡선 그래프 — **안 만든다 (확정).** 실제로 아쉬워지면 그때 다시 본다
