# 공수 기록 : 설명용 그림 툴

> 이 툴 작업의 예상·실제 시간. 툴을 안 가리는 공용 눈금은 저장소 공용 공수기록에 따로 있다.

## 재는 기준

- **AI 가 실제로 붙잡고 있던 시간**을 잰다. 사용자가 답을 기다린 시간은 빼고 센다.
- 단위는 분. 5분 미만은 1분 단위로 적는다.
- 예상과 **2배 넘게** 어긋났으면 왜 그런지 한 줄 적는다.

## 2026-08-21 — 설명용 그림 툴 검토와 고치기

**남이 만든 것을 검토하는 일은 처음 잰다.** 만드는 것과 눈금이 다르다.

| 소단계 | 예상 | 실제 | 상태 |
| --- | --- | --- | --- |
| 1. 설계 문서·코드 읽고 돌려 보기 | 12분 | 14분 | 끝 |
| 2. 의심 가는 곳 시험 파일로 확인 | 5분 | 4분 | 끝 |
| 3. `common.js` 공통 손질 (이름 자름·id·escape·인자) | 4분 | 4분 | 끝 |
| 4. `timeline.js` 고치기 (total·막대 너비·exit) | 3분 | 4분 | 끝 |
| 5. `lint.js` 고치기 (테크 순환·상속·한도·id) | 5분 | 5분 | 끝 |
| 6. `tilemap.js` 고치기 (점프 곡선·범례·기준선·색) | 8분 | 11분 | 끝 |
| 7. `test.js` 회귀 시험 40개 | 6분 | 7분 | 끝 |
| 8. 검토 문서 + 설계·가이드·할 일 고치기 | 8분 | 8분 | 끝 |
| | **51분** | **57분** | |

**어긋난 곳**

- **6번이 8분 → 11분.** 점프 모델을 고치는 건 검사 하나 고치는 일이 아니라 **물리 모델을 다시 정하는 일**이었다.
  포물선 한도를 어디까지 볼지(올라갈 때만 볼지, 내려올 때도 볼지) 정하는 데 시간이 갔다.
  → **모델이 들어가는 검사는 "검사 하나" 눈금(1분)으로 잡으면 안 된다.** 따로 3~5분을 잡는다.
- **6번을 고치자 견본 도면이 틀린 것이 드러나** 견본도 다시 그렸다. 검사를 조이면 견본이 딸려 온다.
- 1번이 예상 안쪽이었던 건 **설계 문서가 잘 쓰여 있어서**다. 근거가 붙어 있으면 검토가 빠르다.

**눈금에 더할 것**

| 이런 일 | 걸린 시간 |
| --- | --- |
| 도구 한 벌(1500줄) 검토 — 읽고 돌려 보고 의심 확인 | **15~20분** |
| **모델이 들어가는 검사 하나** (점프 아크 같은 것) | **3~5분** — 단순 그래프 검사(1분)와 다르다 |
| 회귀 시험 한 벌 (기대값 40개 + 망가뜨려 확인) | **6~8분** |
| 검토 결과 문서 + 관련 문서 맞추기 | **8분** |

## 2026-08-21 — 희귀도 · 채수 열 추가와 ToolTest 폴더

| 소단계 | 예상 | 실제 | 상태 |
| --- | --- | --- | --- |
| 1. 희귀도 열 (서식 + 프로필 한도 + C12) | 3분 | 4분 | 끝 |
| 2. 건물 채수 열 (서식 + C7 수지) | 3분 | 2분 | 끝 |
| 3. `ToolTest/` 로 견본·시험 옮기고 경로 고치기 | 4분 | 3분 | 끝 |
| 4. 전체 돌려 확인 + 문서 정리 | 3분 | 4분 | 끝 |
| | **13분** | **13분** | |

**합계는 맞았지만 안에서 서로 상쇄됐다.**

- **희귀도가 3분 → 4분.** 열 하나 더하는 일로 잡았는데, 한도를 **숫자 하나로도 희귀도별 표로도**
  받게 만드느라 늘었다. → **"설정을 두 가지 꼴로 받는다"는 그 자체로 1분짜리 일이다.**
- **채수는 3분 → 2분.** 곱하는 자리가 두 군데뿐이었다. 앞선 작업에서 수지 계산을 한자리로 모아 둔 덕이다.
- **폴더 옮기기가 4분 → 3분.** `git mv` 는 금방이고, 시간은 **문서 안 경로 고치기**에 갔다.
  → 옮기기 공수는 파일 수가 아니라 **그 경로를 적어 둔 문서 수**로 잡는다.
