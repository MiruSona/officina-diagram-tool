## 1. 검사 10 — 크리티컬 패스

### 1-1. 표기

격자에 **비트 번호 `1`~`9`** 를 찍는다. 시작점 `P` 가 0번이다.

````markdown
```tilemap name="던전 1층" tile=16 move=flat 예시=참
#########################
#....1..#....2...#......#
#..P....+........#...3..#
#.......#........+......#
#########################
```
범례: P=시작 #=벽 .=바닥 +=문 K=열쇠 1=비트 2=비트 3=비트
````

- **번호는 지나갈 수 있는 칸이다.** 바닥 위에 얹는 주석이지 새 지형이 아니다.
- **0 은 안 쓴다.** `P` 가 0번이다.
- 비트가 하나도 없으면 **검사를 건너뛴다.** 대부분의 도면은 비트를 안 찍는다.

### 1-2. 검사 내용 셋

| 무엇 | 언제 알리나 |
| --- | --- |
| **번호 빠짐** | 1부터 이어져야 한다. `1 2 4` 면 3이 빠졌다고 알린다 |
| **번호 겹침** | 같은 번호가 두 칸에 있으면 알린다 |
| **순서대로 못 감** | `P` → 1 → 2 → … 를 차례로 못 가면 **어느 비트에서 막혔는지** 알린다 |

### 1-3. 어떻게 재나

검사 4b 의 flood fill 을 **단계마다 한 번씩** 돌린다. 새 알고리즘이 아니다.

```
지금 자리 = P
주운 열쇠 = 0
비트 1번부터 차례로 :
    지금 자리에서 번져 나간다 (문은 주운 열쇠로 연다)
    그 비트에 안 닿으면  ->  "비트 N 에 못 간다" 하고 멈춘다
    닿으면  ->  지금 자리 = 그 비트
                번지면서 주운 열쇠와 연 문은 그대로 들고 간다
```

**열쇠와 연 문을 들고 가는 것이 핵심이다.** 그래야 *"4번에서 줍는 열쇠로 2번 앞 문을 열 수는 없다"* 가 잡힌다.

### 1-4. 정한 것과 그 까닭

| 정한 것 | 까닭 |
| --- | --- |
| **평면(`4b`) 프로필에서만 켠다** | 중력은 도달성을 점프 아크로 재는데 그 모델을 단계별로 돌리는 건 새로 짜는 일이다. 중력 도면은 대개 한 줄이라 순서가 어긋날 자리도 적다 |
| **비트는 최대 9개** | 한 화면 40×23 에 열 개 넘는 비트를 찍을 일이 없다. 두 글자를 쓰면 한 칸 = 한 글자 규칙이 깨진다 |
| **번호 칸은 지나갈 수 있다** | 비트는 지형이 아니라 그 위에 적는 주석이다 |
| **비트가 없으면 조용히 넘어간다** | 대부분 도면이 비트를 안 찍는다. 없다고 알리면 시끄럽기만 하다 |
| **막히면 거기서 멈춘다** | 2번에 못 갔는데 3·4·5번까지 못 간다고 줄줄이 뱉으면 진짜 원인이 묻힌다 |

### 1-5. 문자표

`1`~`9` 를 **기본** 프로필에 더한다. `던전` 은 기본을 물려받으므로 저절로 따라온다.
**액션(중력) 프로필에는 안 넣는다.** 거기서는 검사 10 을 안 켜기 때문이다.

## 2. 검사 11 — 쉼터 없음

### 2-1. 무엇을 잡나

페이싱 표에서 **강도 4 이상인 구간이 연달아 3개 넘게** 나오면 알린다.

```pacing name="1막" unit=구간 쉼터간격=3 예시=참
| 구간 | 종류 | 강도 |
|---|---|---|
| 1 | 전투 | 5 |
| 2 | 전투 | 4 |
| 3 | 보스 | 5 |
| 4 | 전투 | 4 |   <- 여기서 알린다
```

### 2-2. 지금 검사와 무엇이 다른가

지금은 **"같은 강도가 3번 이어지면"** 알린다. 그래서 `5 4 5 4 5` 는 **하나도 안 걸린다.**
그런데 이건 쉼터가 아예 없는 표다. **"같은 값이 이어지나" 와 "쉴 틈이 있나" 는 다른 질문이다.**

### 2-3. 정한 것과 그 까닭

| 정한 것 | 까닭 |
| --- | --- |
| **센 구간 = 강도 4 이상** | 강도는 0~5 다. 4·5 를 센 구간으로 본다 |
| **한도 3개, 머리말 `쉼터간격` 으로 바꾼다** | **수치 근거를 못 찾았다.** 임의값이라 바꿀 수 있게 둔다 |
| **한 번만 알린다** | 5개가 이어지면 3·4·5번째마다 알리지 않고 그 줄기에 대해 한 번만 알린다 |

## 3. `예시=참` 블록 건너뛰기

### 3-1. 쓰는 법

````markdown
```tilemap name="기호 보기" move=flat 예시=참
```
````

- 이 표시가 붙은 블록은 **검사를 안 돌린다.** 그리기(렌더러)는 그대로 한다.
- 세 도구 모두 같다 — `tilemap` · `timeline` · `pacing` · `count` · `chain` · `cards` · `tech`.
- 보고할 때 **"예시 N개 건너뜀"** 이라고 적는다. 조용히 넘어가지 않는다.

### 3-2. 어디에 붙이나

**설명용 조각에만 붙인다.** `Guide/타일기호.md` · `Guide/도면서식.md` 와 `Design/` 설계 문서 안의 보기 블록이다.
`ToolTest/` 견본에는 안 붙인다 — 거기는 검사가 도는 것이 목적이다.

### 3-3. 왜 이 형태인가

| 다른 길 | 왜 안 쓰나 |
| --- | --- |
| 검사 대상 폴더를 코드에 박는다 | 새 문서를 만들 때마다 코드를 고쳐야 한다 |
| 파일 이름으로 가른다 (`*예시*.md`) | 한 문서 안에 온전한 도면과 조각이 섞이면 못 가른다 |
| **머리말에 표시한다** | **블록 하나 단위로 갈린다.** 머리말 파서가 이미 아무 `키=값` 이나 읽는다 |

## 4. `Docs/` 전체 훑기

### 4-1. 쓰는 법

```
node Tools/Draw/all.js            ← Docs/ 를 다 훑는다. ToolTest/ 는 test.js 가 본다
node Tools/Draw/all.js Docs/Design ← 폴더를 지정할 수도 있다
```

- 폴더 안 `.md` 를 다 찾아 **블록이 든 파일만** 골라 세 도구를 돌린다.
- 잡힌 게 있으면 **exit 1**. 세 도구와 같다.
- 마지막에 한 표로 정리한다 — 파일 수 · 블록 수 · 오류 수 · 건너뛴 예시 수.

### 4-2. 정한 것

| 정한 것 | 까닭 |
| --- | --- |
| **기본 대상은 `Docs/`. `ToolTest/` 는 뺀다** | `ToolTest/` 는 `test.js` 가 본다. 일부러 틀린 견본이 있어 훑기에 넣으면 늘 exit 1 이 된다 |
| **블록이 없는 파일은 조용히 넘어간다** | 42개 문서 중 도면이 든 건 몇 개뿐이다 |
| **HTML 은 안 뽑는다** | 훑기는 검사용이다. 그리려면 도구를 하나씩 부른다 |

### 4-3. 규칙이 바뀐다

`AGENTS.md` 3-1 에 *"`Docs/` 전체를 훑지 않는다"* 고 적어 뒀다. **이제 훑어도 된다.**
그 줄을 고친다.
