# 장르별 설계 도면 조사

조사일 : 2026-08-21
대상 : **설명용 그림 툴** (`Design/2026-08-20-설명용그림툴설계.md`) 을 액션 밖 장르로 넓힐 수 있나
조사한 장르 : **시뮬레이션·타이쿤 / 로그라이크 / 퍼즐 / 덱빌딩**

기존 설계의 근거 조사 두 편(`게임기획서구성조사`, `횡스크롤액션설계도면조사`)이 **둘 다 액션 계열**이라,
1순위(레벨 타일맵)와 검증기가 "공간을 돌아다니는 게임"을 깔고 있었다. 그걸 확인하려고 넷을 병렬로 조사했다.

---

## 0. 결론

### 결론 1 — **툴을 장르별로 나누지 않는다**

네 장르 모두 **새 그림이 아니라 새 검사**를 요구했다. 엔진은 거의 그대로다.

| 장르 | 새 엔진 | 새로 필요한 것 |
| --- | --- | --- |
| **퍼즐** | 없음 | 격자 방언 1개 + **솔버** |
| **로그라이크** | 없음 | 출입구 문자 + **검사 4개** |
| **시뮬·타이쿤** | **C** | 표 서식 + **검사 7개** |
| **덱빌딩** | **C** (같은 것) | 표 서식 + **검사 10개** |

**그림 툴에서 "툴 하나 + 프로필 설정 파일"로 정한 것과 같은 답이다.** 여기서도 툴은 하나,
장르마다 바뀌는 건 **범례 + 켤 검사 목록**뿐이다.

쪼개면 안 되는 이유가 하나 더 있다 — **장르가 섞이는 게임이 흔하다.**
(농장 경영 + 던전 탐험, 로그라이트 + 덱빌딩) 툴을 쪼개면 이런 게임을 못 다룬다.

### 결론 2 — **엔진은 A · B · C 셋으로 끝난다**

| 엔진 | 무엇 | 상태 |
| --- | --- | --- |
| **A. 격자·평면** | 문자 격자 → HTML | 있음. **방언만 늘린다** |
| **B. 시간축** | 표 → 막대 | 있음. **"개수축" 모드 하나 추가** |
| **C. 관계 표 린터** | **표 → 검사 보고서 + Mermaid** | **새로 만든다** |

**C 는 시뮬레이션 조사와 덱빌딩 조사가 따로 요구했는데, 뜯어보니 같은 물건이다.**
생산 사슬(건물·자원)이든 카드 표(카드·아키타입)든 **표를 넣으면 검사 보고서가 나오고 그림은 Mermaid 가 그린다.**

### 결론 3 — **flood fill 하나가 네 장르를 다 먹는다** (이번 조사 최대 수확)

이미 만들기로 한 검증기 4b(던전 이어짐 검사)가 **그대로 재활용된다.**

| 장르 | 같은 알고리즘으로 잡는 것 |
| --- | --- |
| 액션·던전 | 걸어서 못 가는 칸 |
| 로그라이크 | 방 안에서 출입구끼리 안 이어짐 (**들어왔는데 못 나가는 방**) |
| 시뮬·타이쿤 | 시작 자원에서 **만들 수 없는 아이템** |
| 덱빌딩 | **영영 못 얻는 카드** (언락 순환) |

**"열쇠가 그 문 뒤에 있다"** 는 문제가 장르마다 옷만 갈아입고 계속 나온다.
검사기 하나를 잘 만들면 네 장르에서 값어치를 낸다.

### 결론 4 — **"곡선 그래프 안 만든다"가 세 번 더 확인됐다**

기존 설계의 보류 판단이 조사 세 편에서 각각 독립적으로 재확인됐다. **이제 보류가 아니라 확정으로 봐도 된다.**

| 어디서 | 증언 |
| --- | --- |
| 시뮬·타이쿤 | 1849 는 곡선이 아니라 **색칠한 숫자 표**로 밸런싱 |
| 로그라이크 | Slay the Spire 는 **지표 표**(픽률·승률·무엇 대신 골랐나) |
| 덱빌딩 | 비용 곡선이라 부르지만 실제로는 **6칸짜리 표** |

## 1. 장르별 요약

### 1-1. 퍼즐 — 격자를 거의 그대로 쓴다

**Sokoban 업계 표준 텍스트 포맷(XSB, `.sok`)이 이미 우리 표기법과 문법이 같다.** 벽이 `#` 인 것까지 같다.

| | 우리 | XSB |
| --- | --- | --- |
| 벽 | `#` | `#` (같음) |
| 시작 | `P` | `@` |
| 상자 / 목표 / 겹침 | (없음) | `$` / `.` / `*` `+` |

- **해답은 그림이 아니라 문자열 한 줄** — `LURD` 표기 (대문자=상자 밀며 이동, 소문자=그냥 이동). 예 `lluurDDD`
- **기믹 의존 관계는 이미 Mermaid flowchart 로 덮인다.** (Ron Gilbert 가 *Maniac Mansion* 에서 쓴 puzzle dependency diagram)
- 기믹 도입 순서표는 **엔진 B 의 구간 페이싱 표와 형태가 같다.** 재활용

**값어치 : 기계가 실제로 풀어본다.** 다른 장르는 "막힌 데 있나"만 보지만 퍼즐은
① 풀리는가 ② 최소 몇 수인가 ③ **의도한 답 말고 쉬운 우회로가 있는가** 까지 답한다.

Sokoban 은 PSPACE-complete 지만, 사람이 만든 실전 판(우리 기준 40×23 이내)은 A* + 데드락 가지치기로 초 단위에 풀린다.
**단 정량 벤치마크가 아니라 정황 근거다. 솔버에 시간 제한을 반드시 넣는다.**

**덮이지 않는 것** : The Witness 식 선 잇기, 물리 퍼즐, 매치3 확률. 지금 범위 밖이라 보류.

### 1-2. 로그라이크 — 절차 생성이라도 사람이 그리는 건 방 한 장

**Enter the Gungeon 개발사 증언** : *"방을 손으로 짜고 각각을 따로 플레이테스트한 다음 절차 생성으로 잇는 쪽이
더 재밌고 더 공정했다."* 스테이지당 방을 **약 300개** 손으로 그렸다.

즉 **부품(방 템플릿)** 과 **조립 설명서(층 구조 그래프)** 를 따로 그린다.

- **방 템플릿** : 기존 격자에 **출입구 문자 4개 + 머리말 `size` `biome`** 만 추가. 기존 문자는 안 바꾼다
- **층 구조도** : Dead Cells 콘셉트 그래프, Gungeon flow 파일, StS 맵 — 셋 다 **위치 없는 관계 그래프**라 Mermaid flowchart 와 같은 물건
- **진행 곡선** : 구간 페이싱 표의 "구간"을 "층"으로 바꾸면 끝

> ⚠️ **Mermaid 노드 25개 규칙이 여기서 실제로 걸린다.** StS 는 17층 × 6칸 = 102개.
> 층 하나를 노드 하나로 줄이거나 막(act)별로 쪼갠다.

**치명적 실수 : 만들어진 던전을 못 깬다.** 가상의 문제가 아니다 —
Spelunky 2 도 *"생성기가 보통 입구→출구를 뚫지만, 방 안 블록이 무작위라 드물게 출구를 막는다"* 고 기록돼 있고,
Unexplored 는 아예 게임 안에 **"Pray For Help"** 를 넣어 진행을 막는 게 뭔지 게임이 판정하고 고쳐준다.

### 1-3. 시뮬레이션·타이쿤 — 설계 첫날 그래프 하나를 그린다

**1849 개발자(SomaSim, Robert Zubek) 증언** : *"설계 단계에서 모든 자원 사슬을 커다란 방향 그래프로 그렸다.
각 노드가 건물이고 각 간선이 자원이다."* 액션의 타일맵에 해당하는 자리다.

**그런데 그림은 Mermaid 로 이미 된다.** 선례도 있다 — Anno 1800 생산 사슬 렌더러가 실제로 Mermaid 로 그린다(ISC).
**그래서 우리가 만들 건 렌더러가 아니라 검사기다.**

**밸런스는 스프레드시트로 한다. 시뮬레이터를 만들지 않는다.** 1849 방식이 그대로 베낄 만하다 —
마스터 시트에 건물별 생산·소비를 적고, 도시별 순수지를 계산해 **"숫자가 전부 0 근처면 맞은 것"**, 어긋나면 빨강/초록.

> **한계도 개발자가 못박았다** — *"한 번만 도는 시간제한 퀘스트는 스프레드시트로 안 된다."*
> **우리 검사기도 계속 도는 정상상태까지만 노린다.**

**격자는 순위가 확 내려간다.** 배치는 플레이어가 하는 일이라 개발자는 시나리오 시작 맵·방 규격·통로 폭 정도만 그린다.
(다만 이 부분은 직접 증언을 못 찾은 **추론**이다.)

### 1-4. 덱빌딩 — 도면이 아니라 표, 그리고 "구멍 찾기"

**Mega Crit(Slay the Spire) 의 한 문장이 이 장르의 핵심이다.**

> **"Every card should have a place!"** (모든 카드는 자기 자리가 있어야 한다) — GDC 2019

카드 250장 중 **어느 아키타입에도 안 끼는 카드**가 있으면 그게 "자리 없는 카드"다.
사람 눈으로는 못 찾고 **기계가 표를 훑으면 1초**다. 이게 이 장르의 *"이 발판 못 올라간다"* 다.

MTG 는 카드를 채우기 **전에** **설계 뼈대(design skeleton)** 를 만든다 — 빈 슬롯 표다.

```
CW01 – 1 MV
UW09 – Creature removal (usually very efficient)
```

**뼈대는 "빈칸이 어디인지" 보여주는 물건이다.** 타일맵 검증기가 "못 가는 칸"을 잡는 것과 같은 역할이다.

- **시너지는 Mermaid 가 아니라 행렬 표로 다룬다.** 250 노드는 우리 규칙(25개)의 열 배다.
  Mermaid 는 **아키타입 하나를 설명할 때만** 쓴다 (셋업→페이오프, 노드 10개쯤)
- **한 턴 흐름은 엔진 B 로 안 덮인다.** 이산 단계이고 **되돌아오는 고리**가 있다(우선권이 다시 돈다).
  실무 자료도 전부 순서도였다 → **Mermaid `stateDiagram-v2`**
  (예외 : 실시간 카드 게임이라 선딜·후딜이 있으면 그때는 엔진 B 가 맞다)
- **비용 곡선은 6칸 막대다.** 엔진 B 에 "시간축" 대신 **"개수축" 모드**만 더하면 끝

**밸런스 봇은 만들지 않는다.** 학계와 팬 커뮤니티는 활발하지만 **Mega Crit 은 안 쓴다** —
사람 플레이테스터 + 자체 메트릭 + Discord 피드백 18,168건이었다. 슬라이드에 태도가 적혀 있다 :
*"Don't Rely On Metrics Too Much! Data is evidence, but not a conclusion."*
게다가 봇은 **게임이 다 만들어져야** 돌릴 수 있는데, 우리는 설계 단계 도구를 만드는 중이다.

## 2. 함정 — **순환은 장르마다 뜻이 다르다**

이번 조사에서 제일 위험했던 발견이다. 순환 참조를 무조건 오류로 잡으면 **멀쩡한 설계를 오류로 뱉는다.**

| 그래프 | 순환이 있으면 |
| --- | --- |
| 테크 트리 | **버그.** 반드시 DAG |
| **생산 사슬** | **일부러 넣는다.** 1849 는 *"피드백 루프가 최소 하나는 있는지 확인했다"* |
| 카드 효과 | **버그.** 무한 루프 |
| 언락 순서 | **버그.** 영영 못 얻는다 |

광산이 곡괭이를 쓰고 → 철광석을 내고 → 대장간이 곡괭이를 만들어 다시 광산이 쓰는 구조는 **정상이다.**

> **이것이 "검사를 프로필로 켜고 끈다"가 필요한 이유다.** 검사 목록을 고정하면 안 된다.

## 7. 격자 표기 문자 — 눈이 아프다는 문제

`#` 과 `.` 만으로 된 격자는 실제로 읽기 힘들다. 조사 중 사용자가 지적했고, 타당하다.
다만 **네모 기호(■ □ █)로 그냥 바꾸면 격자가 깨진다.** 이유는 아래.

### 문제 — 글자 폭

| 종류 | 예 | 폭 | 위험 |
| --- | --- | --- | --- |
| ASCII | `#` `.` `@` | **항상 1칸** | 없음 |
| **모호(Ambiguous)** | `■` `□` `█` `▓` `░` `●` | **폰트·환경에 따라 1칸 또는 2칸** | **정렬이 깨진다** |
| 전각(Wide) | `＃` `．` `　`(U+3000) | 항상 2칸 | 섞으면 깨진다 |

**제일 흔한 실수가 여기다.** `■` 와 `.` 를 섞으면 한글 폰트에서는 `■` 가 2칸, `.` 가 1칸이라
줄마다 길이가 어긋나 보인다. **문자 수는 맞는데 눈에는 틀어져 보이는** 최악의 상태다.

### 답 — **정본은 ASCII, 보기 좋게는 렌더러가 한다**

격자를 두 겹으로 나눈다. 이미 설계에 렌더러가 있으니 새로 만들 게 많지 않다.

| 겹 | 무엇 | 문자 |
| --- | --- | --- |
| **정본** (저장 · AI 출력 · 검증기 입력 · git) | 한 칸 = ASCII 한 글자 | `#` `.` `@` … |
| **보기** (사람이 읽는 것) | ① HTML 색칠 격자 ② 터미널·마크다운용 미리보기 | 렌더러가 바꿔 찍는다 |

정본을 ASCII 로 두는 이유 :

- **정렬이 절대 안 깨진다** — 어느 폰트, 어느 터미널, GitHub 웹 어디서나 같다
- **XSB(Sokoban) 표준과 호환**된다
- **AI 가 찍기 쉽고 토큰이 싸다** — 이 툴의 목적이 토큰 절약이다
- 키보드로 바로 친다. IME 안 켜도 된다

### 그래도 텍스트를 눈 편하게 만드는 방법 (같이 쓴다)

**① 바닥을 `.` 대신 빈칸으로.** XSB 표준이 그렇게 한다. 벽 윤곽만 남아 확 읽힌다.

```
#########################
#    C  #        #      #
#       +        #  E   #
#  P    #    E   +      #
```

위험은 편집기가 줄 끝 공백을 지우는 것. **검증기가 "짧은 줄은 빈칸으로 채운다"로 흡수하면 된다.**

**② 칸 사이를 한 칸 벌린다.** 폭이 두 배가 되지만 훨씬 시원하다. 40칸이면 80자라 아직 화면에 들어간다.

```
# # # # # # #
#   . . C   #
#   P .   E #
```

**③ 진짜 답은 HTML 렌더러다.** 색칠된 격자를 브라우저나 Artifact 로 본다.
텍스트는 **AI 와 git 이 읽는 정본**이고, 사람은 렌더러로 보는 게 원래 설계 의도였다.

### 굳이 네모 기호를 정본에 쓰겠다면

**지켜야 할 규칙은 하나다 — 한 격자 안에서 폭을 섞지 않는다.**
전부 모호폭(`■□▓░`)으로 통일하거나, 전부 전각(`＃．　`)으로 통일한다.
그래도 **폰트에 따라 깨질 수 있다는 위험은 남는다.** 정본으로는 권하지 않는다.

### 반영 제안

- 격자 머리말에 **`charset=ascii`(기본) / `charset=block`(보기용)** 을 둔다
- **문자 → 보기 기호 매핑표**를 `Guide/타일기호.md` 에 함께 적는다 (`#` → `█`, `.` → `·` 같은 식)
- 렌더러에 **"마크다운용 미리보기" 출력**을 추가한다. HTML 을 못 여는 자리(터미널·커밋 메시지)에서 쓴다
- 검증기는 **정본(ASCII)만 검사한다.** 보기 겹은 검사 대상이 아니다

## 8. 못 밝힌 것 (다음에 확인)

- **시뮬·타이쿤에서 개발자가 레벨 배치 도면을 안 그린다**는 직접 증언을 못 찾았다. 구조에서 나온 **추론**이다
- RimWorld · Dwarf Fortress · Frostpunk 는 밸런싱 방법 1차 증언을 못 찾았다
- Hades 가 방을 어떻게 저술하는지 공개 증언을 못 찾았다
- Sokoban 솔버의 **정량 벤치마크**(판 크기별 소요 시간)를 못 찾았다. 정황 근거뿐이다
- 카드 무한 루프 검사(C6)·자원 되돌림 검사는 **문헌 근거 없이 자명해서 넣은 것**이다
- 매치3 의 sink 비율 "95~105%" 수치는 모바일 라이브 서비스 블로그라 **근거가 약하다**
- Tiled TMX · Scryfall · Magic Set Editor 라이선스 미확인
- **모호폭 문자가 실제로 어느 환경에서 깨지는지** 직접 시험해 보지 않았다 (유니코드 규격 근거)
