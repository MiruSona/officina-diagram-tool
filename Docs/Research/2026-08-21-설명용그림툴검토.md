**설계는 튼튼하다. 구현에 거짓 음성(놓치는 것)이 하나 있었고, 그게 견본에서 실제로 터져 있었다.**

- 설계에서 제일 값어치 있는 부분은 **"안 만들 것" 목록**이다. 근거가 붙어 있고 범위를 지킨다.
- **"타일맵은 그림이 아니라 2차원 배열"** 이라는 판단이 이 툴 전체를 지탱한다. 맞는 판단이다.
- 장르 차이를 **프로필**로 흡수한 것도 맞다. 툴을 장르별로 쪼갰으면 섞인 장르를 못 다뤘다.
- **가장 큰 구멍은 "검사가 안 잡는 것"을 재는 장치가 없었다는 점이다.** 아래 1장.

## 1. 제일 큰 문제 — 놓치는 것을 아무도 안 봤다

완료 판정(설계 9장)은 **"잡아야 할 것을 잡나"** 와 **"안 잡아야 할 것을 안 잡나"** 는 봤다.
그런데 **"잡아야 하는데 조용히 넘어가나"** 를 보는 항목이 없었다.

그 결과 실제로 이런 일이 있었다 :

> `DiagramTool/Test/견본-중력.md` 는 **사람이 실제로 못 깨는 도면**인데 검사 4a 가 "문제 없음" 을 냈다.

원인은 점프 모델이 **너무 너그러웠던** 것이다. 옛 모델은 공중에서 **높이 예산과 가로 예산을 따로** 썼다.
그래서 *"최고 높이까지 올라간 채로 최대 거리만큼 옆으로 간다"* 가 됐다. 실제로는 그럴 수 없다.

**고친 것** : 설계 3-2 가 이미 `h` · `x_h` · `v_x` 세 값이면 곡선이 정해진다고 써 놨는데
검사 4a 가 `x_h`(정점까지 거리)를 **안 읽고 있었다.** 이제 읽는다.

| 가로로 간 칸 수 | 올라가 있을 수 있는 최고 높이 |
| --- | --- |
| `x_h` 이하 | `h` — 달리는 속도를 줄이면 정점이 앞으로 온다 |
| `x_h` 초과 | `h × (1 − ((m − x_h) / x_h)²)` — 포물선을 따라 떨어진다 |

내려오는 중에는 이 한도를 안 본다. 낙하는 막힌 곳을 숨기는 쪽이 아니라서 너그럽게 둔다.

**남은 한계** (일부러 그대로 둔 것)
- 공중에서 방향을 되돌리면 가로 칸 수를 두 번 세서 **실제보다 빡빡하게** 잰다. 잘못 잡는 쪽이라 안전하다.
- 더블 점프 · 대시 · 벽타기는 아직 안 본다. 설계 10장에 이미 적힌 유보다.

## 3. 고친 것 — 실제로 돌려서 확인함

### 엔진 A (`tilemap.js`)

| # | 무엇 | 어떻게 확인했나 |
| --- | --- | --- |
| A1 | **점프 곡선 반영** (1장) | `견본-중력.md` 가 못 깨는 도면임을 잡아냈다. 도면을 닿게 고쳤다 |
| A2 | **검사 2 가 범례도 본다** | 범례에서 `K` `+` 를 빼고 돌려 잡히는 것을 봤다 |
| A3 | **기준선 표를 이동 축으로 고른다** | 전에는 파일의 **첫 표**를 썼다. 평면용 표가 먼저 있으면 중력 도면에 엉뚱한 값이 갔다 |
| A4 | **기본값을 쓸 때 알린다** | 문서엔 "표가 없으면 건너뛴다" 고 적혀 있었는데 실제로는 4/5 를 **조용히** 썼다 |
| A5 | 타일 색을 `profiles.json` 으로 옮김 | 문자를 늘릴 때 두 군데를 안 고쳐도 된다 |
| A6 | HTML 로 뽑을 때 이름·라벨 escape | 도면 이름에 `<` 가 들어가면 결과 HTML 이 깨졌다 |
